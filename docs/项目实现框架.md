# 项目实现框架

## 1. 当前首关

水墨主题“云栈烟岚”，34 段路线、64 处高低平台，总路程 952.5 米。基础速度 11 米/秒，熟练路线通过加速板可约 68 秒完成；未利用跳板的基础路程约 87 秒，碰撞和复活会增加用时。横向移动连续，最多可移至 ±10 米，越过屋顶侧缘会掉落。

7 名选手共用确定性赛道与规则，包含玩家和 6 名 AI。每局玩家横向位置随机、始终从最后一名起跑；NPC在其前方近处分布2名、其余4名分散在约90—210米外的屋顶。AI 速度从 10.74 到 11.39 米/秒，策略分为入门、常规、熟练三个梯度：前方障碍扣分、跳板加分，并保留少量决策随机性。每名选手使用独立固定随机种子，便于复测。

屋顶边缘通过赛道足迹查询自动触发跳跃，重力和竖直速度模拟落地。这个版本使用解析几何采样代替每名角色每帧的物理射线，支持高度差、左右分叉、再汇合及建筑立面接触的首关。若加入弯道、任意旋转地形或复杂斜坡，需要扩展赛道坐标系或换成射线/扫掠检测，不能直接沿用当前 Z 轴距离排名。

## 2. 代码职责

| 模块 | 职责 |
|---|---|
| `main.gd` | 状态切换、开局、镜头、排名、结算与性能采样 |
| `track_data.gd` | 模块布局、平台查询、障碍/金币/跳板数据、平台高度、正面/侧面墙体扫掠查询 |
| `runner.gd` | 玩家/AI 共用运动、自动跳跃、碰撞、复活、动画切换 |
| `world.gd` | GLB 实例化、可见范围控制、金币/粒子 MultiMesh 批量绘制 |
| `hud.gd` | 原生矢量 UI、竖横屏布局、触摸命中、商店/任务/榜单 |
| `save_data.gd` | 本地存档、金币、皮肤、每日奖励、本机最佳纪录 |
| `platform.gd` | Godot 与 JS 的原生能力边界、广告结果和后台暂停 |
| `audio.gd` | 4 个复用音源、轻量 MP3 循环与提示音 |
| `tools/wechat/` | 原生 wx API 桥接与开放数据域 |

状态：主页 → 3秒倒数 → 竞速 → 结算。失足后自动回退到最近一次站稳的屋顶，落点较该安全位置后退约3米并离边缘至少0.9米；不暂停比赛、不弹窗、不看广告、不依赖检查点。自动恢复有短暂碰撞保护，不额外硬直。

屋顶高度在 -0.8—9.4 米之间变化；15处三路分叉通过左、中、右不同高度的楼体形成选择，之后汇合。所有金币、跳板、障碍、投影与终点使用同一份平台高度数据。角色正面碰到更高楼体时进入 Climb，以3.5米/秒爬升并在楼顶前沿翻上去；侧面碰到墙体进入 SideSlide，以前进速度72%沿墙移动、以1.2米/秒缓降，播放滑铲姿态；离开墙尾或动作结束后恢复空中状态。侧滑时镜头向接触墙面的外侧偏移，防止角色被楼体遮住。比赛奖励与结算双倍金币广告仍各采用幂等发奖。

## 3. 美术与生产

所有 3D 几何均由 `tools/create_assets.py` 在 Blender 中生成，米制单位、1单位=1米、角色约1.8米。GLB 采用 +Y 向上、+Z 面朝前；顶点色、单材质与共用128²纸纹。每个模型同时保留压缩 `.blend` 源文件，统计见 `art/asset_manifest.json`。

| 分类 | 资产 |
|---|---|
| 角色 | 玩家斗笠浪客433三角面；NPC基础火柴人、头带款、胸带款196/208/208三角面 |
| 动画 | Run、Jump、Land、Flip、Hit、Celebrate、Climb、SideSlide；NPC7骨骼；玩家9骨骼（含披风和武器） |
| 可拆配饰 | 帽子、背包、莫西干发型、王冠、耳机 |
| 地形 | 青石板、木栈道、屋檐、石桥（旧城市场景模块保留作资源库） |
| 交互 | 墨痕／云纹踏板、竹篓、屏风、铜铃、铜钱与卷轴终点门 |
| 远景 | 水墨群山、雾卡、亭台、古塔和竹丛 |
| 特效 | 墨点、烟墨拖尾、淡墨扩散、卷轴展开和朱砂印章；动态粒子共用20实例 |
| UI | Godot 矢量绘制按钮、卡片、进度和排名，无位图依赖 |
| 字体 | Noto Serif SC 中英宋体子集，500/800字重，SIL OFL |
| 音频 | 程序合成的5类提示音及12秒循环，统一MP3 |

目前全套 45 类模型共3756个唯一三角面；单角色 ≤433，单场景模块 ≤128，低于给定上限。完整资产数量与字节数以构建清单为准。斜坡和转角已提供美术模块，当前首关使用高低平台与左中右三路分叉，尚未实现任意角度转向竞速。

顶点色在Godot运行时通过Shader读取。若GLB在另一工程使用标准材质，应勾选 `vertex_color_use_as_albedo`。NPC采用低饱和墨色与飞白着色。玩家采用独立材质，仅把红色飘带区域替换为皮肤配色，斗笠、灰袍和武器保留原色，旧帽子不与斗笠重叠。玩家 `.blend` 包含预览相机并默认静态姿势；8套NLA动作保留，取消对应轨道静音可检查动作。

UI 使用引擎绘图而不是 Blender 位图，以避免字体与多分辨率 UI 纹理占包；3D 资产完全来自 Blender。远景使用6张低面数山形网格与6张雾卡，搭配亭台、古塔与竹影。山体边缘用淡墨透明Shader融入背景；低端模式减少到4层山与3层雾。高级后处理、实时阴影及大纹理均未启用。

## 4. 微信适配

- 首包：适配器、加载界面、配置、原生桥接、开放数据域。
- `engine` 分包：社区适配的 WASM/JS 引擎与本关 PCK（沿用模板的 `empty-tips.bin` 文件名）。
- 同一资源包内含本关和全部轻量皮肤。将来内容增长时，再通过社区 `godot_subpack_runtime` 生成具备依赖清单的 PCK 分包；当前没有伪造空皮肤包或未实现的远程加载流程。
- `JavaScriptBridge` 访问 `SkylinePlatform`，在原生环境调用 wx 存储、分享、视频、云存储与开放数据域接口。
- 桌面使用 `user://skyline_save.json`；微信优先 `wx.getStorageSync/setStorageSync`。每日任务按 UTC+8 日期刷新，JSON 数值读取时归一化为整数。
- 广告位缺失、加载失败、提前关闭均不奖励。没有“点击分享即验证成功”的奖励逻辑；分享面板无法证明真实分享完成。
- 好友数据只在开放数据域中读取，主域仅把共享画布合成到屏幕。当前只实现好友排行和本机榜，没有全球联网排行榜或防作弊服务器。
- 微信使用原生触摸流，桌面才启用鼠标模拟触摸。切后台自动暂停，回来后由玩家继续。
- 竖/横屏分别导出两个 `deviceOrientation` 配置，UI 根据视口比例调整布局，不声称微信运行中可随意旋转屏幕。

## 5. 性能设计

1. Compatibility / WebGL2，无实时阴影、无屏幕空间效果、无复杂材质；简化墨色着色 + 环境雾。
2. 屋顶只保留玩家后27米、前74米的绘制窗口，道具前72米，金币前48米；NPC在玩家前52米、后10米内选最近的两名绘制；其余暂停动画绘制，继续模拟竞赛进度。
3. 金币与20个固定粒子分别通过 MultiMesh 合并绘制。角色共用导入网格、骨骼结构和动画资源。
4. 碰撞使用平台足迹和障碍 AABB 查询，不引入动态刚体或大批 Area3D。
5. 游戏开始时创建场景对象，竞赛期间不反复创建/销毁障碍与粒子。UI StyleBox 缓存复用，音源池复用；菜单切换允许实例化角色，便于清理单局状态。
6. 设备标记低端时，3D 渲染分辨率降至75%、关闭粒子。连续3次低于29帧时降至70%，UI仍保持原分辨率。
7. 打包脚本实际统计主包字节并对4MiB硬门槛报错，模板下载固定版本及SHA256，避免上游静默替换。

这些是实现与实测范围，不构成低端手机性能认证。完整手机验收矩阵与测量边界见性能报告。

## 6. 后续扩展位置

新增直线关卡可将 `TrackData` 的常量和布局移到数据资源；本版先保证一个关卡完整闭环。任意弯道需要引入路径弧长和局部横向坐标，同时改动角色前进方向、摄像机和平台采样。竞技服务器、全球榜和广告安全校验可通过独立 HTTPS 后端扩展，不把 AppSecret 放入客户端。

参考：[Godot Web 导出文档](https://docs.godotengine.org/en/stable/tutorials/export/exporting_for_web.html)、[社区微信模板及源码](https://github.com/godothub/godot-minigame)、[微信官方开放数据示例](https://github.com/wechat-miniprogram/minigame-canvas-engine)。


NPC在地面行进时与前方对手保持约32—34米间距，空中不急停。领先超过70米时以66%巡航速度前进，接近后恢复完整策略，让远处对手可被逐步追上。


## 7. 水墨版本美术与Shader

详细实现见 `水墨风格实现.md`。当前场景只实例化水墨平台、古建与竹林，旧的城市模型留在资源库供回退，但不在比赛画面中绘制。UI已改为Noto Serif SC宋体子集；原始Noto Sans SC作为旧资源保留。新增水墨模型的3D几何仍全部从Blender导出。
